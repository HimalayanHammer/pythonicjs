Verified against CPython

        

            The test suite generates thousands of cases, hand-picked edge cases plus seeded random fuzzing, and runs each one
            through pythonicjs and through CPython 3.13. The results, including which exception is raised, must be identical.
            That is why these all behave exactly like Python:
        

        
    
            
  • round(2.5) is 2 and round(2.675, 2) is 2.67: half-to-even on the exact binary value.
    • 
            
  • sum of ten 0.1s is exactly 1, like Python 3.12's compensated summation.
    • 
            
  • int('١٢') is 12 and int('12px') raises ValueError.
    • 
            
  • sorted(['a', 1]) raises TypeError instead of silently mis-sorting.
    • 
            
  • heapq produces the same heap layout as CPython, and most_common breaks ties the same way.
    • 
            
  • Format specs like '{:=+10.3e}', '{:_b}' and '{:,.2%}' produce the same text.
    • 
        

    


    

        
Usage

        

            

                
ES modules (tree-shakable)


import {range, zip, Counter, itertools} from 'pythonicjs'
import {combinations} from 'pythonicjs/itertools'
import {heappush, heappop} from 'pythonicjs/heapq'

            

            

                
Global mode, for scripts and REPLs


import 'pythonicjs/global'

print(sum(range(10)))
print(new Counter('hello').most_common(1))

            

            

                
Browser


<script src="https://unpkg.com/pythonicjs"></script>
<script>
    print(sorted([3, 1, 2]))
</script>
